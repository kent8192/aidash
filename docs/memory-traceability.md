# Native memory traceability

This matrix links each memory requirement to its decision, owning Issue,
implementation, evidence, and acceptance status. It is the reference for
[architecture](architecture.md#memory-contracts), [memory recovery](memory-recovery.md),
[memory evaluation](memory-evaluation.md), and the [Registry boundary](operations/registry-capabilities.md#native-memory-providers).

Revision: `origin/develop/0.1.0` at `db6b210f6020f7600b44e7bb55091040b16db049`.
Every implementation and evidence path below is relative to that revision.

## Status meanings

The five statuses are independent. A row is `yes`, `partial`, `unverified`, or
`n/a` for each status. Do not infer one status from another.

- **Selected**: the technology or requirement is chosen in an approved decision.
- **Implemented**: code at the revision above performs the behavior.
- **Fixture-verified**: deterministic tests with fakes or synthetic providers pass.
- **Live-quality-evaluated**: a real model or provider was measured for answer or retrieval quality.
- **Release-accepted**: the user approved the release scope and thresholds.

`unverified` means the repository does not record the evidence. It does not mean
the behavior is absent.
