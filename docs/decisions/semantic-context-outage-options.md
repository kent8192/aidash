# Semantic context when the embedding provider or vector backend is unavailable

Investigation for [#154](https://github.com/kent8192/aidash/issues/154), prepared against `develop/0.1.0` at `13a6f144`. The behavior below is pinned by regression tests added with this document; no runtime behavior changes. The recommendation below was adopted on 2026-10-12 and is [recorded on #154](https://github.com/kent8192/aidash/issues/154#issuecomment-6120720336); section 6 states the decision and section 5 links the filed follow-ups.

## Decision in one paragraph

Adopted: **option 1 (degrade with an explicit marker), narrowed**: only optional workspace semantic context of a **local** Run may degrade, only after a bounded transient retry, only when the Registry-declared context source opts in, and only with a typed, journaled, visible marker. Everything else stays fail-closed: required-Home remote semantic context, every authorization, credential-binding and provider-contract failure, native memory banks, and every source that is not explicitly marked optional. **Independently of the option chosen**, a local Run must stop failing hard on an outage: today it ends `Failed` after one attempt while a required-Home Run retries and pauses with a typed reason. Options 2 and 3 are not taken now (option 2 is impossible under #158, option 3 hinges on an undecided Provider Catalog question and costs an operational dependency); option 4 is the right stance for the contexts that must fail closed.

## 1. What happens today

Established by running the new tests against `develop/0.1.0`, not by reading code alone. "Step" is one `worker_once` of the Harness. The local column records the behavior before [#233](https://github.com/kent8192/aidash/issues/233); see section 7 for the current behavior.

| Cause during a step                                    | Local Run (`auto_context` on)                                                                                                                                                                                                                                                                                  | Required-Home remote Run                                                                                                                                                                                                           |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Embedding provider answers HTTP 503                    | One attempt, no retry. The Run enters `Waiting(FailureDelivery { target: Failed })` with `error = "semantic backend unavailable or invalid; inspect index status and retry"`. The next step makes the Run and its Task `Failed`. No model request. `recovery.retry` and `recovery.semantic_reason` stay empty. | Transient `unavailable`: retry with a persisted delay of 2, 4, 8, 16 and 32 s; the sixth failure pauses the Run with `retries_exhausted`. Manual resume continues and keeps the attempt history. No model request. (existing test) |
| Embedding provider refuses connections                 | Same as 503, and the provider receives no query call.                                                                                                                                                                                                                                                          | Transient `unavailable`, `retry.count = 1` after the first failed step.                                                                                                                                                            |
| Embedding provider never answers                       | Same as 503 after the 20 s client timeout (3 s to connect).                                                                                                                                                                                                                                                    | Not run; every non-`RemoteSemantic` Home failure takes the same classification path as a refused connection.                                                                                                                       |
| Vector backend holds no points for the indexed sources | Same outcome, and the query is not even embedded: point presence is checked first.                                                                                                                                                                                                                             | Transient `unavailable`, `retry.count = 1`.                                                                                                                                                                                        |

Evidence:

- Local: `local_auto_context_step_fails_the_run_when_semantic_retrieval_is_unavailable` (four cases) in `server/src/apps/knowledge/tests/semantic.rs`, renamed and flipped by #233 (section 7).
- Required-Home: `semantic_retry_exhaustion_pauses_and_manual_resume_keeps_attempt_history` (existing, 503) and `required_home_semantic_outage_is_a_typed_transient_failure_for_every_cause` (new, refused connection and missing points) in `server/src/apps/identity/tests/scoped_remote_execution.rs`.

### Why the two paths differ

Every embedding failure is reduced to `SemanticUnavailable` (`aidash-application/src/semantic/embedding.rs`) and a missing vector point to the same error (`retrieval.rs`). The server's `classify_failure` (`server/src/apps/execution/repositories/worker.rs`) maps only the remote `RemoteSemantic(reason)` to `ExecutionFailure::Semantic`, which `aidash-harness/src/recovery.rs` retries and then pauses. A local `SemanticUnavailable` falls into the `_ => Other` arm, is not retryable, and is delivered as a terminal failure. The collapse also hides the cause: `SemanticClient` (`aidash-integrations/src/semantic.rs`) reports an ordinary upstream HTTP 401–403 as `RemoteSemantic(Configuration)` and a malformed or mismatched answer as `RemoteSemantic(ProviderContract)`, and `embedding::invoke` turns **every** provider error into `SemanticUnavailable`. The only exception is a Tenant-backed provider whose failure the Credential Broker recognizes as a capability failure (`Invalid`, `NotFound`, `Forbidden`, `Conflict`); those are preserved, but only `Forbidden` then pauses (`Authority`): the others take the same `_ => Other` arm and end the Run (section 2). So a rejected key and a response-contract violation are indistinguishable from an outage on the local path. The difference is an accident of error mapping rather than a decided policy: the Issue's expectation ("an outage stops every step") understates it, because a local Run is not stopped but destroyed, and its Task with it.

### Scope of the exposure

- The failure applies to the Run's retrieval request before inference (`Executor::advance`, `ordered_semantic_context` / `semantic_context`). It does not occur when the index is disabled or `auto_context` is off.
- An Ordered Run reuses its retrieval while its Retrieval Key holds and rechecks authority without embedding (ADR 0020). From reading the code, such a Run survives an outage that starts mid-Run until its key changes (a new input, an index revision). A Legacy Run retrieves on every step. This reading is not covered by a test in this PR.
- Inference itself can be healthy: both paths stop before the model call, so the model request count is zero in every case above.

### Not covered by these tests

- The native memory bank path (`agent.memory`), which has its own recovery-serving gate and is exercised by `native_memory.rs`.
- A revoked or missing Provider Credential Binding. These are not outages: with a Tenant-backed embedding provider, `Invalid`, `NotFound`, `Forbidden` and `Conflict` are deliberately preserved instead of becoming `SemanticUnavailable` (`embedding.rs`), and a missing binding rejects admission before the Run exists (`docs/provider-credentials.md`).
- A PostgreSQL outage as the vector backend. Since ADR 0023 the vector backend is the application's own PostgreSQL pool, so it fails together with all durable state, which #156 row 4 accepts. The only independent vector failure left is missing or unreadable points, which the tests cover.

### What #158 changes

- The Provider Catalog admits only providers whose OAuth flow issues a credential, so today's only entry is OpenRouter. A second embedding provider cannot be added, which makes option 2 **unavailable** until a second OAuth provider exists.
- Embeddings and inference then share one OpenRouter Provider Credential per Tenant. A revoked or missing binding stops both, so degrading embeddings buys nothing in that case, and by the table above must not be attempted. Option 1 helps in one scenario: **OpenRouter inference is healthy while its embedding route or model is down**, or the vector points are unavailable.
- Open Catalog question for option 3: whether a keyless in-deployment embedding model needs a Provider Catalog entry has not been decided. `EmbeddingConfig.validate_parameters` currently accepts only `openai` and `openrouter`. If the answer is yes, a keyless entry contradicts "each entry has a credential-issuing OAuth flow" and needs an ADR amendment.
- PR #219 (Phase 2 removes `credential_env` for embeddings) resolved an earlier finding: RequiredHome remote semantic search used to reject any `provider_credential` embedding configuration, which would have left a required-Home workspace embedding configuration with no valid form. The Home now embeds a Tenant-backed source as its Tenant's memory-retrieval maintenance (ADR 0006), so a missing or revoked Provider Credential Binding fails at the embedding call after the same search and disclosure authority checks. The required-Home half of a decision therefore depends on the same OpenRouter Provider Credential as inference.

## 4. Recommendation

Choose option 1, narrowed as follows.

### What may degrade and what must fail closed

| Context                                                                                      | On outage                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Optional workspace semantic context of a local Run (`auto_context`, Registry source opts in) | Retry like a required-Home Run: five retries after delays of 2, 4, 8, 16 and 32 s. If the sixth attempt still fails, **degrade**: continue with a marker.                                                                   |
| Same context without the opt-in (default)                                                    | Typed transient pause (`retries_exhausted`, manual resume), the behavior a required-Home Run already has. Not a terminal failure.                                                                                           |
| Required-Home remote semantic context                                                        | Unchanged: typed retry then pause. Never degrades, because receipts and dependency journals are part of the disclosure contract.                                                                                            |
| Native memory banks and any source declared required                                         | Fail closed with a typed pause.                                                                                                                                                                                             |
| Authorization, binding, provider-contract, invalidation, budget and allowance failures       | Fail closed with a typed pause. In-step Credential Broker capability failures (`Invalid`, `NotFound`, `Conflict`) and provider-contract failures are terminal on the local path today; follow-up 1 gives them typed pauses. |

### The marker

The memory bank already reports `{"status": "disabled" | "no_space"}` where it cannot supply content (`memory_context.rs`). A local Run's `semantic_memory` is the envelope `{"workspace": <semantic>, "memory": <memory>}` built by `memory_context::combine`, so the marker takes the same status shape in the **workspace** slot and leaves `memory` as it is. Healthy native memory is still delivered, and the schema seen by the model does not change:

```json
"semantic_memory": {
  "workspace": { "status": "unavailable", "cause": "embedding_provider" },
  "memory": { "status": "disabled" }
}
```

`cause` is one of `embedding_provider` or `vector_backend`. Today both reduce to the unit variant `SemanticUnavailable` (`embedding::invoke` and `PreparedSearch::check_points`), so the cause cannot be chosen where degradation happens until follow-up 1 preserves it. It carries no endpoint, status body or query text. Rules the marker must follow:

1. **Not cached.** A degraded result must not be stored as the Source observation under the Retrieval Key (ADR 0020), or the Run would stay degraded after the provider recovers. The next step retries.
2. **Journaled.** Record the degraded step in the Run's events so the Task history and the API show that the step ran without semantic context, with the same typed cause.
3. **Visible.** The Run inspection API and the web UI show it. Degradation that only the model sees is a silent substitution.
4. **Opt-in.** The Registry-declared source descriptor carries `on_unavailable: pause | degrade` with `pause` as the default, frozen into the Run's binding snapshot like the Context Policy of ADR 0010.
5. **Bounded.** Optional, but a Run that degrades on every step for a long time should still surface it; a per-Run count in the inspection output is enough.

### Why not the others

- **Option 2**: impossible under #158 and, even if a second OAuth provider existed, doubles indexing cost and adds a disclosure target for a failure class the marker already absorbs.
- **Option 3**: moves the single point of failure into the deployment and depends on an undecided Catalog rule; revisit once the Catalog question is answered and only if degradation proves unacceptable for real workloads.
- **Option 4 alone**: leaves the inconsistent local/remote behavior and destroys a Task over a transient provider outage.

## 5. Follow-up Issues

Filed after the decision: item 1 → [#233](https://github.com/kent8192/aidash/issues/233); items 2–5 → [#234](https://github.com/kent8192/aidash/issues/234); item 6 is handled inside [#158](https://github.com/kent8192/aidash/issues/158) ([PR #219](https://github.com/kent8192/aidash/pull/219)); item 7 → [#235](https://github.com/kent8192/aidash/issues/235); item 8 → [#236](https://github.com/kent8192/aidash/issues/236).

1. **`fix(execution): treat a local SemanticUnavailable as a typed transient semantic failure`**. Map `SemanticUnavailable` to `ExecutionFailure::Semantic(Unavailable)` so local Runs retry and pause like required-Home Runs. Stop `embedding::invoke` from collapsing key rejection (401–403) and `ProviderContract` into `SemanticUnavailable`, so only a real outage is transient and the other classes keep their typed pauses. Preserve the outage cause: replace the unit `SemanticUnavailable` with a typed cause (`embedding_provider` from `embedding::invoke`, `vector_backend` from `PreparedSearch::check_points`) and carry it through `classify_failure`, so the marker of item 3 can name it. Map in-step Credential Broker capability failures that `embedding::invoke` preserves (`Invalid`, `NotFound`, `Conflict`) to the typed `Authority` pause instead of the terminal `_ => Other` arm. Updates the four local regression tests added here, which currently pin the terminal failure.
2. **`feat(registry): declare on_unavailable (pause | degrade) on context sources`**. Descriptor field, validation, binding-snapshot freezing and migration of existing sources to `pause`; part of the #110 descriptor work.
3. **`feat(harness): degrade optional semantic context with a typed unavailable marker`**. Marker shape, no Source-observation caching, journaled event, interaction with the Retrieval Key and ordered reuse.
4. **`feat(api,web): show semantic context degradation on Runs`**. Run inspection field, event and UI state for a step that ran without semantic context.
5. **`docs: record the semantic context outage policy as an ADR and add the "Degraded context" term`**. Proposed wording is in the PR description.
6. **`fix(federation): define the embedding credential for required-Home semantic search after #158`**. RequiredHome search rejects Tenant-backed embeddings while #158 removes environment-backed ones; decide the supported path (relates to PR #219).
7. **`decision: does a keyless in-deployment embedding model need a Provider Catalog entry?`**. Gate for option 3; no implementation until answered.
8. **`test: Ordered Run keeps working through a mid-Run embedding outage while its Retrieval Key holds`**. Pins the reading in section 1 that is currently derived from code and ADR 0020.

## 6. Decision (2026-10-12)

- Option 1, narrowed as in section 4, is adopted.
- `degrade` stays opt-in per source: `on_unavailable: pause | degrade`, default `pause`.
- The local path retries like required-Home before degrading: five retries, six failed attempts in total.

## 7. Local Run behavior since #233

- A local semantic outage is typed `RemoteSemantic(Unavailable)` where it occurs, and `classify_failure` maps it to the transient `unavailable` semantic failure. The outages are an embedding transport failure (including a response body that breaks off), timeout or HTTP 408/429/5xx; vector points missing from the backend; and a transient database failure of the PostgreSQL vector backend. This holds for semantic search and for native-memory recall. A local Run retries after 2, 4, 8, 16 and 32 s, then pauses with `retries_exhausted`. Its Task is not failed. Manual resume continues a semantic search Run. A native-memory recall whose memory model operation has spent its own retry ledger pauses again on resume, until #291 gives a resumed Run a fresh ledger.
- A replay while a native memory model attempt is still inside its call deadline is `pending`. The Run retries it after 1 s and then every 30 s, because each replay repeats the whole semantic-context step, including its charged workspace embedding. A Home serving a remote Run leaves its operation `WAITING` for 1 s. Neither spends an outage retry, however long the call deadline is. A memory engine job waits for the attempt the same way, without using up one of its attempts.
- `SemanticUnavailable` is not transient. It also reports invariant, allowance and index-state violations and permanent vector backend failures, which retrying cannot fix.
- `embedding::invoke` no longer collapses an upstream key rejection (HTTP 401–403, `configuration`) or a contract violation (`provider_contract`) into `SemanticUnavailable`. Both pause the Run at once with their typed reason and are not retried.
- Evidence: `local_auto_context_semantic_outage_is_a_typed_transient_failure_for_every_cause` (four causes), `local_semantic_outage_pauses_after_bounded_retry_and_resumes_when_the_provider_recovers` and `local_semantic_key_rejection_and_contract_violation_pause_without_retry` in `server/src/apps/knowledge/tests/semantic.rs`.
