# SSE acceptance coverage

This maps the accepted [specification](../design/2026-09-30-sse-event-delivery-specification.md)
to executable checks and the implementation boundary they exercise. Run results,
build identity and measured thresholds are in the [verification report](sse-delivery-results.md).

| Contract | Evidence |
| --- | --- |
| AT01: separate writer, execution consumer and SSE receivers | `writer_a_execution_b_and_sse_c_have_independent_delivery` in [process tests](../../tests/sse_delivery/process.rs) uses three native API processes. Broker permissions allow only B to pull the shared execution consumer; A writes and every replica receives. The exact event's broker sequence is acknowledged. All three replicas show notification-caused reads without initial, fallback or reconnect assistance. |
| AT02: authorized scoped fan-out | `hints_are_scoped_untrusted_and_loss_recovers_from_postgres`, `global_stream_filters_revoked_workspaces_without_rewinding_on_restore` in [SSE tests](../../tests/sse_delivery.rs), and `subject_credentials_enforce_workspace_isolation_and_live_revocation` in [authorization tests](../../tests/authorization.rs). The retained-generation unit test also verifies that unrelated scope receivers do not change. |
| AT03: hints cannot supply data or authority | The untrusted-hints case covers uncommitted/rolled-back records, malformed/wrong-Node envelopes, forged sequence/data and arbitrary `dataref`. `Hint` in the [subscriber](../../src/sse/broker.rs) deserializes identifying metadata only; data/reference fields have no fetch or frame-construction path. The oversized process case verifies a real publisher-generated reference delivers the exact canonical body. |
| AT04: initial-read and read/wait races | `notification_during_initial_authority_read_is_retained` in [edge cases](../../tests/sse_delivery/edge_cases.rs) holds the real ownership row lock while a notification arrives, then releases it with the fallback delayed. `wakeup_survives_read_to_wait_gap_and_scopes_are_reclaimed` in [hub tests](../../src/sse.rs) deterministically signals after the observed read generation and before waiting. Initial replay and reconnect reconciliation cover pre-registration hints. |
| AT05: loss, duplication, reordering and continuous traffic | The untrusted-hints case checks ordered canonical replay and recovery without a hint. `duplicate_flood_preserves_fallback_and_idle_revocation` keeps publishing duplicate hints while unrelated fallback and idle revocation progress, with no audit growth for empty checks. `audited_frames_allocate_sequences_only_after_serialization_lock` blocks two real frame audits at the database advisory lock, proves no sequence is allocated while waiting, and verifies each frame retains its ordered decision pair after release. |
| AT06: bounded replay and denied pages | `bounded_pages_drain_denied_history_and_preserve_cursor_contract` drains 550 records, including 325 denied records and 225 eligible records, without waiting for the 60-second fallback. [The reader](../../src/sse/connection.rs) awaits page consumption before advancing and cooperatively yields between 100-record raw slices. |
| AT07: cursor/resume compatibility | The bounded-pages case checks Last-Event-ID precedence, malformed headers, old/zero/negative/future cursors and gaps. Process cases reconnect on another replica after graceful and forced shutdown. Browser code and the JSON replay endpoint retain their existing behavior. |
| AT08: current authority while idle and buffered | Six `browser_invalidation_closes_idle_and_unpolled_buffered_streams` cases cover session revocation, absolute/idle expiry, mapping disablement, identity disablement and operator-grant removal with retained unread bodies. `buffered_resource_revocation_filters_without_rewinding` checks resource-only denial and restoration; existing [authorization](../../tests/authorization.rs) and [resource authorization](../../tests/resource_authorization.rs) cases cover policy/credential revocation and resource dependency rules. |
| AT09: visibility and independent liveness | Both `closed_gate_suppresses_reads_and_resumes_without_a_new_hint` cases hold the real durable gate, observe no event queries, retain independent authority checks, distinguish server waits from output backpressure, and verify resumption or cleanup without another body poll. The resume case also receives the 15-second keepalive. |
| AT10: broker lifecycle | `replicas_recover_broker_outages_and_replay_after_shutdown` starts with an unavailable broker, establishes subscriptions, interrupts connections, deletes the business stream, restarts NATS and verifies PostgreSQL fallback/recovery. [The supervisor](../../src/sse/broker.rs) separately bounds connect/subscribe/flush at five seconds and retries with jitter. |
| AT11: slow readers, cleanup and large events | `unpolled_output_expires_but_idle_streams_and_authority_checks_remain_live` retains an unread response while another reader progresses, proves admission reuse and keeps an empty idle stream live. `oversized_reference_notification_replays_canonical_bytes` exceeds the actual broker payload limit, verifies canonical payload equality and records API-process RSS before/after. Gate cancellation checks the waiting gauge returns to zero without body polling. |
| AT12: shutdown and crash | The three-process outage case verifies bounded SIGTERM drain, forced kill and replay on another replica. Stream cancellation releases registrations, pending raw pages and admission. The UI subscriber does not delete shared broker objects. |
| AT13: settings and observability | Hub unit tests reject invalid recovery/body deadlines; subscriber tests reject malformed or wrong-Node metadata. Live process metrics prove readiness, causal reads, connections and canonical progress. Gate tests verify waiting counts; [connection-option tests](../../src/bus/connection.rs) verify credential-free transport addresses/errors, and the exclusive-consumer fixture exercises authenticated NATS. |
| AT14: accepted workload | [The benchmark](../../tests/sse_delivery/benchmark.rs) enforces three 30-second active windows with 100 connections on three API processes, plus three 60-second idle windows per version. Every event/client pair, per-event slowest receipt, causal counter and SQL reduction is checked; failures are retained by the [reproduction script](../../scripts/test-sse-delivery.sh). |

The UI subscriber shares only the canonical Event representation and Node subject
with execution. It does not own execution ACKs, Agent routing or Run activation.
The [operations runbook](sse-delivery.md) documents settings, metric semantics and
the PostgreSQL fallback.
