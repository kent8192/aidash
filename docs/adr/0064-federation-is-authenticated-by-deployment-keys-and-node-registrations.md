# Federation is authenticated by Deployment Keys and Node Registrations, not by shared Peer Credentials

Federation used one shared bearer secret per pair of Deployments (a Peer Credential), which only
Deployment Administrators could configure. Once Nodes inside Tenants are the parties of
Federation (ADR 0028), that model puts Aidash staff in the path of every cross-Deployment
cooperation on Cloud, and a per-Node shared secret cannot be read back by the server on Cloud,
where the Secret Store is write-only for the application host. Each Deployment therefore holds a
Deployment signing identity and signs short-lived tokens that name the sending and receiving Node. A
receiving Node accepts only Nodes that its Tenant Administrators registered, and the Node
Registration pins the sending Deployment's public key. Within one Tenant there is no
registration: the Tenant's policy decides over the sender's own subject.

## Considered Options

- **Keep Peer Credentials between Deployments and add Node Registrations on top.** Every
  cross-Deployment cooperation would still need a Deployment Administrator first, which is a
  support case on Cloud (#363). Rejected.
- **A shared secret per pair of Nodes, managed by Tenant Administrators.** People would exchange
  secrets by hand, and on Cloud the server could send one only through the Credential Broker
  (#310). Rejected.

## Consequences

- Peer Credentials, `credential_env` and the Deployment Administrator's peer list are removed.
  Deployment Administrators keep one Deployment-wide switch that allows or forbids Federation with
  other Deployments.
- The Deployment Key lives in KMS on Cloud and Dedicated. On Self-hosted it is a file named in the
  settings and generated by `manage`.
- `/.well-known/aidash` publishes the Deployment identity and its public key, never a list of
  Nodes. A Node's address names its Deployment and its Node name, never its Tenant, and the
  sending Tenant's name leaves the protocol and the Peer Mapping key.

Amended 2026-10-27 (#486): this ADR once also let a Peer Graph Grant pin the other Deployment's key, so a named Deployment Administrator of another Deployment could read one Tenant's graph. #301 removed Peer Graph Grants and #486 deleted the token variant, the grant table and the grant routes. Every inbound caller is now a Node with a Node Registration, and protocol `0.5` refuses `0.4`.
